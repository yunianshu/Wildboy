# 用户身份、会员等级与独立优惠

## 操作

网页后台的「会员管理」或小程序「我的 → 管理员 → 会员管理」使用相同接口。管理员先新增等级，再搜索用户编号分配身份。用户在「我的身份」查看完整用户编号；多个“微信用户”昵称相同时应核对编号，不凭昵称猜测。等级可以停用，不删除历史。

1. 设置等级名称。
2. 分别开启活动或商品优惠。每项选择折扣、固定价或立减，填写数字后保存。
3. 搜索用户，选择散客、会员或领队；会员再选一个启用中的等级。

业务身份与权限分离：散客、会员、领队仍是 USER，只有原有 ADMIN 能管理。普通用户不能自行升级，领队不会获得查看其他人的资料或管理权限。管理员账号不在待分配会员用户中。

## 金额和业务范围

- 前端输入元、折；后端金额用整数分，折扣用万分比。例如 8 折是 8000，8.5 折是 8500，固定 50 元是 5000。
- 折扣四舍五入到分，然后乘数量。固定价不会高于原价；立减最低到零。不叠加其他业务的优惠。
- 商品按每件计算。服务端报价和下单重算，客户端不能提交身份、会员级别或最终价来改变优惠。新客户端带预期总价，若规则或商品价格改变，返回冲突并要求重新确认。
- 活动优惠开启时必须明确选择「同行全部享受账号等级价」或「每单最多 1 个优惠名额」。没有默认选择。后者只限制优惠人数，不证明报名账号本人参加，也不按同行者手填手机号识别会员。两者均以已登录报名账号的服务端等级为准。
- 新等级默认不开启任何业务优惠，既有用户迁移为散客，既有价格与订单不被重新计算。等级停用后新单恢复原价，历史订单仍保留当时价格。

## 数据和并发

会员分配、等级规则均使用版本号；冲突需重新加载，不自动覆盖。下单在事务中锁定用户身份和等级规则，再锁活动或商品，冻结原价、优惠价、等级名称、规则版本与计价方式。更新等级、改名、停用或调整用户身份不会改变既有订单付款和退款金额。

商城免支付订单使用 CONFIRMED_FREE，显示“免支付已确认”，不产生微信交易号或支付时间、不调用微信扣款；可发货或在发货前取消。真正收款继续使用原有验签、商户/AppID/付款账号/金额核对与退款流程。

完整用户列表仅管理员可读，不返回外部微信标识。个人身份接口只返回当前会话用户。审计仅存操作人、对象、动作和时间，不记录参与人/地址/电话/凭据。

## 会员 API

- GET /api/v1/me/membership：当前用户业务身份、等级与完整用户编号。
- GET /api/v1/admin/membership/tiers：所有等级及活动、商品两项独立规则。
- POST /api/v1/admin/membership/tiers：创建等级。
- PUT /api/v1/admin/membership/tiers/{id}：更新，必须带 version。
- GET /api/v1/admin/membership/users?query=&customerType=&page=0&size=20：按昵称或完整编号检索普通用户，支持身份筛选与服务端分页。
- PUT /api/v1/admin/membership/users/{id}：{customerType,tierId,version}，MEMBER必须指定启用等级，其他身份不带等级。
- GET /api/v1/shop/products/{id}/quote?quantity=1：当前账号商品报价，必须登录。

等级请求：name、sortOrder、enabled、version、rules。rules必须包含ACTIVITY、SHOP各一项，共两项。每项包含scope、enabled、pricingMode（DISCOUNT/FIXED/REDUCTION）、pricingValue和participantPricing。participantPricing只允许ACTIVITY的ACCOUNT_ALL或ONE_BENEFIT，活动规则启用时必填，其他业务为null。

## 验收要求

- 身份和会员管理入口真实可达；普通用户与领队管理接口均403，匿名401。
- 折扣/固定价/立减、三范围隔离、无默认活动多人规则、0元、整数边界、停用、无效输入覆盖。
- 报价变更拒单且不占库存；重复下单只占一次；历史快照、支付金额及退款金额不受改等级影响。
- 两端保存冲突、重复点击、分页、切号、页面退出后的晚响应隔离和表单离开保护覆盖。
- 所有原有测试保留；仅为新增NOT NULL快照列补齐旧退款测试的合成插入数据，未降低断言。

运行记录另见本次验收文档。自动化网关模拟不代表真实微信支付、真机或生产部署验收。
