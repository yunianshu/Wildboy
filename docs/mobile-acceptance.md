# 小程序管理与补全页面：独立验收

## 从需求定义的验收条件

用户确认了管理员设计，并要求“代码也一并实现”。范围是小程序内活动管理与用户活动浏览、个人中心、报名记录、报名成功流程；保留网页后台，支付仍关闭。

1. 普通微信用户不显示活动管理操作；直接打开管理页面仍会校验服务端角色，不能仅依靠隐藏入口。
2. 管理员使用服务端已有管理员账号验证。密码不持久化、不记录日志，登录失败不获得管理会话。
3. 管理员可创建草稿、编辑完整活动字段、选择封面、发布、取消并查看报名名单；报名截止、时间、容量与版本冲突由后端复核。
4. 新建和编辑中重复点击不重复提交；取消对话框不执行操作；过期会话或换账号后不能继续用旧授权操作。
5. 名单只对管理员显示，切换账号或离开后不能残留敏感数据；分页请求不能混入别的活动名单。
6. 普通用户可从活动列表和详情报名，成功页面必须来自真实成功响应，并验证是当前账号的报名，不凭链接参数伪造成功。
7. 我的报名只显示当前登录用户记录；分页、取消报名、状态与空态明确，不冒充已完成现实活动。
8. 各页面 loading/error/retry、返回与取消流程可用，页面路由和 WXML 事件绑定齐全。
9. 微信支付不启用、装备不下单，不增加真实账号权限或自动绑定管理员身份。

## 独立审查发现并回归修复

- 无效编辑 ID 原本可能在 onShow 后变为新建空表单：现在明确拒绝，不静默创建。
- 名单点击查看号码时如管理员权限已失效，原本只显示错误而保留已加载名单：现在清除授权、名单和私有电话缓存。
- 失效管理会话在写入途中产生会话版本变化，页面仍需清除表单与授权，不因过早返回漏掉清理。
- 移动 helper 源文件后原构建可能残留旧 dist 文件：构建先清理生成目录，防止旧文件混入微信包。

这些回归不放宽原断言，不以跳过测试或假成功替代失败处理。

## 可复验命令

从项目根目录：

```sh
npm --prefix miniprogram ci
npm --prefix miniprogram test
node --test tests/e2e/mobile*.cjs
```

GitHub 工作流在小程序构建后执行独立 Page 流程脚本。HTTP 数据库回归仍使用 `tests/e2e/run-api-smoke.sh`，仅对回环隔离测试服务创建合成记录，不能用于真实运营服务器。

## 界面与权限说明

“我的”显示当前已校验账号身份；只有服务端 ADMIN 才显示“活动管理”。普通用户可以看到较低优先级的“管理员身份验证”入口，但该入口只允许输入运营者已有管理员凭据，不授予权限、不把微信普通用户变成管理员。管理账号与微信账号为不同身份，其报名归属不会自动合并。

装备继续仅展示，所有报名仍免费。页面上的按钮存在不表示已经获得真实微信能力配置或上线许可。
