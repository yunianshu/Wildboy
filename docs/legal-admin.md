# 协议管理

网页后台导航“协议管理”，小程序管理员“我的 → 协议管理”均可维护隐私政策和用户协议。两端使用相同的服务端草稿、发布版本与管理员权限。

## 操作流程

1. 验证管理员身份后选择“隐私政策”或“用户协议”。未发布时不提供自动生效的模板。
2. 填写标题（1–120 字）和纯文本正文（去空白后 10–50000 字）。不支持可执行 HTML 或富文本脚本。
3. “保存草稿”只保存待审核内容，不改变小程序线上协议。
4. 预览完整内容，确认由运营方审核后点击“发布新版本”，再二次确认。
5. 发布后成为当前版本，用户使用相关登录/报名服务时须确认当前两份协议版本。旧版本和历史同意记录保留。

每次草稿保存/发布使用修订号防止覆盖他人修改。409 冲突时保留当前输入并禁用覆盖式重试，先复制需要保留的内容，再重新加载。切换协议或离开未保存页面时提示；会话失效则优先清理私有内容，不以未保存提示阻碍退出。

历史版本只读，不能通过前端编辑历史。正文用文本展示，不使用任意 HTML 渲染。小程序编辑框明确设置 50000 字上限，避免默认 140 字截断。

## 运营与平台边界

本功能是协议内容和版本管理工具，不提供自动合规判断或经过法律审核的正式条款。发布内容由运营方负责审核。微信平台的《用户隐私保护指引》及相关接口声明需在微信管理后台单独配置，自建协议不能代替平台配置。

生产环境没有正式协议时，用户相关功能显示尚未就绪，不偷偷使用开发演示条款。管理员身份验证与协议维护不受该条件阻碍，方便首次配置。

## 验证说明

网页组件测试覆盖保存不发布、发布二次确认、取消确认、版本冲突保留输入、只读历史、HTML 安全显示与会话清理。小程序 Page 流程由独立测试执行。模拟 DOM/Page 测试不等同真实浏览器或微信真机验证；本轮未声称微信后台配置、真实法律内容或正式发布已完成。
