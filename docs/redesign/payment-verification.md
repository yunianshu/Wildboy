## 支付接口补充验证

新增 `server/src/test/java/com/wildboy/PaymentHttpContractTest.java`，**22/22 通过，0 失败/错误/跳过**。使用 MockMvc 执行 Spring Security、控制器、真实 Auth/Shop/Refund 服务及隔离 PostgreSQL；这是接口集成测试，不冒充监听端口的 22 次真实网络请求。

| 契约组 | 已验证内容 |
| --- | --- |
| 预支付 | 五个原生支付字段及 JSON `package`、服务端金额和付款人传递；匿名/非属主/开发身份/商户未配置拒绝 |
| 查询与履约 | 预支付后查单确认 PAID，再按版本发货；不由客户端结果直接改为已付 |
| 支付回调 | 临时密钥 RSA 验签、AES-GCM 解密、四个原始请求头及 body 转交；重复回调不改变版本、paidAt、交易号、库存，入账审计仅一次 |
| 错误通知 | 签名篡改、缺头，以及有效签名但 appId/商户/付款人/JSAPI/金额/币种/订单/交易状态不符时拒绝入账；取消单不复活、异交易号不覆盖原交易 |
| 取消与不确定结果 | 预支付超时保留 intent/reconciliation 与库存；取消先关闭渠道，重复取消只回库一次；关闭结果未知时保留库存，明确关闭后才释放 |
| 整单退款 | 真实退款服务的申请、审核、签名回调及主动核对；权限/版本校验、签名或金额错误不回库，只有确认成功才回库一次 |

入站支付和退款回调委托真实本地 parser 验签解密，只有出站预支付/查询/关闭/退款网关调用被模拟。此前旧成功 fixture 中 appId 与模拟 appId 同为 null 的弱断言也已修正为明确的非空测试值。独立审查确认没有模拟 ShopService 入账后只验证 200 的假阳性。

最终完整 `mvn verify` **138/138 通过，0 失败、0 错误、0 跳过，BUILD SUCCESS**，包括新增 22 项以及修正后的旧成功 fixture。日志：`test-results/payment-http-contract-server-verify.log`；原有 116 项结果继续保留在原重设计日志。本轮“本地完整流程及支付接口测试”验收完成。

模拟微信网关仅存在于测试上下文，不访问常驻 19080 QA 数据库，不替换运行服务的真实身份和商户校验。模拟网关返回的成功、PAID/SHIPPED/退款状态是本地接口测试结果，不是实际扣款、发货或到账事实。
