# 收费活动订单设计与边界

## 与免费报名隔离

收费活动使用 activity_order、activity_order_participant、activity_order_refund，免费活动继续使用原 registration。免费报名取消重报会复用记录并重写参与人，不能承载付款历史；收费订单每次重新报名产生新订单，原参与者和价格快照保留。活动退款不调用商城回库存逻辑。

活动创建/普通编辑 DTO 保持 priceCents=0 的兼容合同；管理员在草稿价格入口单独设置收费价格。复制活动及由模板生成的新草稿保留源快照的原价，不自动发布。当前 API 见 [活动订单 API](../activity-orders-api.md)。

## 会员计价

活动和商品规则互相独立。活动规则默认关闭，启用时必须显式选择 ACCOUNT_ALL（同组全部使用报名账号等级价）或 ONE_BENEFIT（每单最多一个优惠名额）。不根据姓名、手填手机号或参与者顺序判断本人身份，也不由客户端传会员资格。

订单保存活动标题、参与者快照（身份证加密）、人数、原价/实付总额、等级ID/名称/版本、规则方式/数值、优惠人数和策略版本。金额按整数分运算并限制溢出；改等级或规则不改变已创建订单。

## 事务与状态

锁序为用户、会员等级、活动、活动订单。下单验证当前协议、参与者、可报名状态与容量，保存价格及人员快照后占名额。请求指纹保证同一用户和幂等键不能被改成另一组参与人。

正价订单 PENDING_PAYMENT，经可信微信结果确认才 PAID。零价订单直接 CONFIRMED_FREE，不调用微信或记录假交易。付款意图先提交，再调用网关，超时不能抹掉可能已创建的交易。

未付关闭必须先可靠核对并关单；结果未知时继续保留名额。退款仅在微信成功后改 REFUNDED 并释放名额，同一通知不会重复释放。退款未知可用原退款号重试；CLOSED恢复已付状态，后续新申请保存独立历史。活动整场取消需要先结清所有订单，不能一条SQL清空未确定资金的名额。

## 权限、审计与通知

业务身份不改变USER/ADMIN权限，领队不能读取其他人资料或执行后台操作。个人订单/参与者/退款按当前账号隔离，管理员操作审计记录真实管理员。

已付、免支付确认及退款处理中参与者纳入行前和变更通知。组织者关闭或退款的订单记录取消标记，结清后整场取消仍通知这些账号；不把自愿取消者重新归类。微信订阅权限与配置仍需满足，站内排队不等于微信送达。

## 明确保留的范围

- 收费候补未开放，免费活动候补不变。将来支持收费候补须定义获得名额后的付款期限和过期规则，并复用相同锁序及资金保护，不能直接通过旧 registerPriority 绕过付款。
- 仅整单全额退款。部分同行退出与单个优惠名额如何分摊退款尚无规则，不提供部分退款入口。
- ABNORMAL退款需人工核对微信状态，不自动换号重开。
- 真正商户收款、退款、回调公网可达、真机与生产部署验收尚未执行。
