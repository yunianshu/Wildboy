# Wildboy 管理后台

Vue 3 + TypeScript + Vite。管理功能独立于微信用户端，登录、活动、名单、商品、订单、退款与通知工作台均使用真实 `/api/v1` 后端接口。支付由小程序发起，管理端不创建虚假支付或报名成功状态。

## 启动

需要 Node.js 24.12+（已在 24.22.1 验证），安装后端所需服务并启动 Spring Boot。

```bash
cd admin
npm ci
npm run dev
```

开发地址 `http://localhost:5173`，Vite 将 `/api` 和 `/assets` 代理至 `http://localhost:8080`。后端地址可通过 shell 环境变量 `API_PROXY_TARGET` 修改。不将 API 地址或凭据硬编码到客户端。

管理员账号/密码由后端安全配置。前端没有默认管理密码，禁止用微信用户身份冒充管理员。

本地联调可复制 `.env.example` 为 `.env.local`，设置 `VITE_ENABLE_DEV_LOGIN=true`，且后端必须启用开发配置。该入口同时要求 Vite `DEV` 模式，生产构建不展示或执行开发登录。开发入口不能替代生产身份认证。

## 可用流程

- 管理员登录、退出；会话仅保存在浏览器内存中，刷新后需重新登录，不写 localStorage/sessionStorage。
- 活动分页及服务端分类筛选；标题/状态清楚标记为「当前页筛选」，不伪装成全库查询。
- 草稿创建/编辑；原创封面预设和 HTTPS/`/assets/` 地址；图集、摘要、详细说明、地点、集合点、时间、人数。
- 所有日期按 Asia/Shanghai 解释和显示，不受操作人员设备时区影响。
- 保存草稿后单独确认发布；取消发布确认框不会触发发布。
- 已发布活动编辑，确认取消活动；不删除历史，不承诺系统自动通知已报名成员。
- 版本冲突不自动覆盖，提示重新加载后人工核对；保存未完成时阻止重复操作。
- 离开未保存页面时确认；取消活动只读。
- 名单按报名单分页，一笔报名可展示多位参与人；手机号和身份证号默认遮罩、逐人显隐。离开名单页面销毁已加载个人信息。无默认导出或日志输出。
- 空、加载、网络错误、权限错误、会话过期、重试等状态。
- 仅免费活动：活动 payload `priceCents=0`，校验禁止非零金额。
- 商城管理支持商品创建/编辑、价格、库存、上下架和乐观锁；订单显示服务端支付状态与微信交易号，收货资料默认遮罩，只有已支付订单可确认发货。

管理员可上传 PNG/JPEG，服务端检查实际类型、大小并重新编码；上传目录通过 `MEDIA_DIR` 配置并需持久化。封面也可选预设或填写 HTTPS 图片地址。外链图片应配置平台白名单，配置 referrerpolicy 避免发送后台来源信息。图片输入不能执行脚本。

## 构建与测试

```bash
npm run typecheck
npm test
npm run build
```

单元/组件测试覆盖日期偏移及无效日期、免费金额/人数限制、图片 URL、会话存储、过期登录、403、409、失败登录、成功导航、空列表和确认框取消等。根目录独立端到端测试用于配合真实后端验证发布/编辑/报名名单。

## 部署

将 `dist/` 放到 HTTPS 静态服务；同源反向代理 `/api/v1` 到后端、`/assets` 到后端或静态图片目录。使用 hash 路由，无需业务路由重写。避免直接将开发 Vite 服务暴露到公网；生产管理员认证、限流、TLS、审计和备份需由服务端/部署层保障。当前内存 token 减少持久存储暴露，但仍需 XSS 防护，客户端不渲染用户 HTML。

## 技术依据

- Vue 官方推荐 Vite 的 TypeScript 单文件组件工具链：https://vuejs.org/guide/quick-start.html

## 文章编辑与官方介绍

「文章管理」统一维护普通图文文章，不区分固定文章类型。新建时填写标题、摘要、封面，可选关联活动；保存信息后可添加文字、图片、表格，并独立保存图文。封面和非空正文齐备后才能发布。未保存修改会阻止发布，离开时提示确认。

- 草稿仅管理员可见；已发布文章才会在小程序展示。
- 已发布文章为只读，先「下架并编辑」再修改；下架立即停止公开展示。
- 已发布文章可「设为官方介绍」，确认后原子替换首页「野小子」入口指向的文章。其他已发布文章展示在探索页底部轮播；被替换的旧官方介绍仍是普通已发布文章，会回到轮播，若不需要展示可将其下架。
- 官方介绍下架后入口显示暂无内容；重新发布后需再次设置官方介绍，不会自动选择其他文章。
- 版本冲突不会自动覆盖，通过「重新加载文章」核对最新版本；保存中的操作不可重复提交。
- 不预置或自动发布示例介绍文章，实际内容由管理员编辑发布。
