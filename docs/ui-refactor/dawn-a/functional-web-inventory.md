# Web 功能驱动设计清单

日期：2026-11-18。范围：当前实际生产路由与业务代码；不参考 B 设计、历史画板或旧 UI 截图。A 仅提供绿白视觉语言，不作为信息架构。此文是功能审查，不宣称新设计已经实现或完成流程测试。

## 依据与权限基线

- `admin/src/router.ts`：21 个有效页面路由；`/`、`/waitlist` 与通配项仅重定向。WaitlistView.vue 虽存在，但不在有效路由中，不恢复候补业务。
- `admin/src/api.ts`：登录只接受 ADMIN；token 仅保存在内存，刷新重新登录；请求统一 /api/v1；401 清会话；409 提醒重新读取；sessionVersion 隔离切号前请求。
- `server/src/main/java/com/wildboy/SecurityConfig.java`：/api/v1/admin/** 服务端要求 ADMIN，而不是由导航可见性决定权限。
- `admin/src/types.ts`：活动、商品、订单、用户、消息状态与金额分字段契约。
- `PRODUCT.md`：业务目的和保护约束辅助来源；与代码矛盾时以代码为准。本次未使用旧 docs/product-scope.md 的“无收费报名”说法。

以下“管理员”均包含上述公共权限基线。角色调整、管理员账号配置、支付/退款状态等另受服务端能力与版本约束；不能把新设计中的快捷按钮当作新的授权或接口。

## 从管理员任务出发的新信息架构建议（待设计，不是现有新增功能）

1. **今日处理**：以现有 dashboard/exceptions 为依据，把待发货、支付待核对、退款待处理、消息失败、发货上报失败集中为可追到原对象的任务入口。统计必须注明时间范围；异常不能伪造为全部业务待办。低库存提供商品入口，不凭空增加采购流程。
2. **活动全生命周期**：活动列表以“准备中→已发布→出发管理/报名→取消”理解任务，但实际状态仅DRAFT/PUBLISHED/CANCELLED，不新增服务端“已结束”状态。模板作为新建活动的复用入口；订单/免费名单围绕选中活动进入，避免管理员重复寻找活动。
3. **交易与履约**：清楚分开活动报名订单、商品订单、商品退款、微信上报。共享“金额/支付与退款/参与人或收货人/履约动作”阅读顺序，保留各接口状态差异。详情先给对象、状态、下一步，危险动作附当前金额和后果。
4. **用户与权益**：用户资料、管理员权限、业务身份分别说明，避免把会员等级误当系统权限。会员设置用活动/商品两列与折扣/固定价/减价直观选择；活动参与人适用范围放在活动规则旁，不做多级审批。
5. **内容与平台**：文章、协议、首页入口、微信订单中心、管理员账号各有独立保存边界。平台接入问题只显示配置状态和实际错误，不用通用“已完成”覆盖平台确认。
6. **跨模块对象关联**：活动→订单/名单→用户；商品→订单→退款/发货→上报；异常→原订单；通知→关联活动。先展示对象上下文和返回位置，不能只有多个孤立菜单。
7. **桌面/窄屏**：桌面使用有意义的字段横向对照；窄屏按对象摘要、关键数值、可用动作分组，筛选不遮挡主要任务；不是把旧B卡片改绿。绿白主色不承担支付/失败/草稿的唯一状态表达。

## 画板必须覆盖的状态与流程

- 列表：初始加载、已加载刷新、空数据、无筛选结果、错误重试、无权限、分页边界。
- 表单：校验错误、上传中、提交中、未保存离开、版本冲突、结果未知、成功且实际回读。
- 订单：待付/已付/免费确认/关闭/退款处理中/已退款；确认动作必须显示订单与金额，退款不被设计为“立即到账”。
- 隐私：默认脱敏→说明对象用途→用户确认→揭示→离页/切号清理。
- 权限：可改权/不可改权原因；账号配置可用/不可用/失败，不靠只隐藏按钮表示授权。
- 通知/平台：重试入队与真实送达分别呈现；未配置、授权缺失、失败、未知结果各有不同下一步。
- 编辑器：元数据与正文双草稿、源列表加载失败、保存后再发布；不增加业务未支持的课程/候补/分类删除。

## 审查边界

本次读取了全部有效视图的输入绑定、接口路径、函数和关键流程，并核对 types/api/router 与服务端统一权限入口。没有逐个重跑后端控制器规则，也没有新做真实支付、消息或生产环境联调。新设计必须继续以实际接口能力为边界；后续任何新增动作须另行确认需求与服务端实现。
