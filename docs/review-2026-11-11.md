# 小程序问题复查与修复记录

日期：2026-11-11。开始审查前已在 `main` 执行 `git pull --ff-only`，没有需要合入的远端更新，基线为 `e70f4ca`。本轮包含功能、异步状态、错误恢复及操作步骤审查；验收结束时修改保留在工作区，尚未提交、推送或部署。

## 已修复的问题

| 范围 | 问题与修复结果 |
| --- | --- |
| 微信管理员登录 | 已验证的微信账号被授予 ADMIN 后，前端仍按普通 USER 校验而拒绝登录。现在接收真实的微信 ADMIN，继续校验账号来源及微信验证状态。 |
| 管理员入口 | “我的”错误地用当前角色推断密码登录入口，个人资料刷新还会覆盖独立的入口能力状态。现在以公开能力接口为准；能力失败可以单独重试，离开页面的旧请求不会覆盖新状态。 |
| 登录页恢复 | 能力查询期间离开后再返回可能一直缺少管理员入口。返回时补查尚未完成的请求，失败提供就地重试。 |
| 报名结果 | 重复提交返回的已有报名，可能因人数相同被误当成当前草稿提交成功。现在比对实际参与人；已有记录明确展示服务器返回的人员及恢复说明。 |
| 报名断网 | 提交超时、未知失败或离开页面时结果不确定，不能立即修改后重发。现在锁定草稿并先查询本人有效报名，查不到后保留草稿允许重试；禁止重试加载打断正在提交的请求。 |
| 首页与活动列表 | 首页返回时刷新活动名额和商品信息；活动首屏失败后不能直接加载第二页，重试始终从第一页开始。 |
| 商城分类 | 重复进入可能覆盖正在进行的分类请求，旧分类请求失败又可能污染新分类。现在保留真实请求及选择范围；缓存中不存在的选项回到全部。 |
| 消息列表 | 刷新、隐藏时清理分页状态；没有更多数据时不继续请求，分页结果按 ID 去重。 |
| 退出账号 | 退出确认期间账号已经切换时，不再退出新账号；退出后同时清理个人及协议状态，确认框异常可恢复。 |
| 商品原价 | 界面允许留空，但保存校验拒绝空原价。现在留空使用现价，继续阻止原价低于现价。 |
| 分类编辑 | 切换分类仅改变选中项，表单与版本仍是旧分类。现在立即装载对应名称、排序和版本；未保存草稿切换时确认，保存中禁止交叉操作。 |
| 名单筛选 | 前端发送的报名状态没有进入后端查询，导致列表与总数不按状态过滤。后端现在先过滤再分页，列表、总数和导出一致。 |
| 名单导出 | 每页请求 100 条超过后端 50 条上限，且忽略当前筛选。现在以 50 条遍历全部匹配页，去掉任意页数截断；导出期间防止重复点击和切换筛选，CSV 公式样式文本按文本转义。 |
| 协议更新 | 下单时发现协议版本变更后容易停留在无法继续的状态。现在清除旧勾选并加载当前版本，加载失败提供就地重试。 |

## 操作步骤简化

| 场景 | 修复后的操作 |
| --- | --- |
| 登录、报名、下单同意协议 | 两份协议链接均可主动查看；勾选同意后即可继续，不再强制分别打开两份阅读器。仍按当前版本校验，未默认勾选。 |
| 首次报名完善联系人 | 提交时先引导补齐本人资料，避免先填参与人再被要求重复填写；“保存并返回报名”直接回原报名页，姓名与手机号预填到第一个空白参与人。 |
| 下单新增或修改地址 | 从结算进入时使用“保存并使用”，保存后直接返回结算并选中，无须再点一次地址；独立地址管理页仍保留管理行为。 |
| 编辑商品分类 | 提供“编辑当前分类”和“新建分类”直接入口；切换分类后立即显示正确表单，无须额外加载。分类操作按钮分组排布，避免窄屏文字挤成竖排。 |
| 查看报名状态 | 全部、已报名、已取消横排展示，并突出当前选项；导出明确针对当前筛选。 |
| 按钮尺寸和文字 | 收紧主次按钮高度与重复留白，使用 Flex 水平、垂直居中；订单结果的两个操作并排展示，查看订单改为轻量入口。修复订单小按钮行高与内边距叠加变高、资料弹窗按钮超出容器被裁切的问题。 |
| 表单可辨识性 | 地址文本框补齐边框、背景及紧凑高度；补齐通用图标尺寸和关闭按钮居中，避免弹窗关闭图标不可见。 |
| 数量与筛选控件 | 商品数量加减图标改为双向居中；订单六个筛选选项紧凑等分排布，避免每个短标签占用半屏。 |
