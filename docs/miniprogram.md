# Wildboy 微信小程序

## 技术与目录

原生 TypeScript + WXML + WXSS。无 WebView、无 H5 替代页面，`npm run build` 生成微信开发者工具可读取的 CommonJS JavaScript 与原生模板。官方类型来自 [wechat-miniprogram/api-typings](https://github.com/wechat-miniprogram/api-typings)。

首页实际遵循第三张参考图的结构，不包含参考图中的无关业务内容：沉浸式轮播 → **2×2 大图分类** → 装备商城入口 → 双列活动列表触底分页。分类名称按原需求保留「本周活动 / 国内游行 / 假期活动 / 休闲活动」。商城包含真实商品、库存与订单，开发演示商品明确标注，不代表真实库存或售价。轮播图、分类和装备使用项目生成的原创示意图片，出处见 `asset-provenance.md`。

## 启动

```sh
cd miniprogram
npm ci
npm run typecheck
npm test
npm run build
```

在微信开发者工具导入 `miniprogram/`，配置已指向 `dist/`。`touristappid` 仅用于导入检查，必须通过本地 `project.private.config.json` 设置你自己的合法小程序 AppID 才能验证真实微信登录、体验版、真机与发布。不要把 AppSecret 放进客户端或仓库。

在 `src/config.ts` 设置自己的 HTTPS API **origin**（不含 `/api/v1`）。默认 `https://api.example.invalid` 会明确报服务尚未配置，不会返回伪造的成功数据。

本地联调先启动后端 dev profile，再执行 `npm run dev:local`。脚本只把生成的 `dist/config.js` 设置为本地 HTTP origin 和开发登录，可用 `WILDBOY_LOCAL_API` 覆盖地址；`src/config.ts` 的生产 fail-closed 配置不变。只有微信运行环境 `envVersion === 'develop'` 才允许 HTTP 与 `/auth/dev-login`；体验版和正式版即便误带这个标记，也仍走真实微信登录且拒绝 HTTP。微信工具的本地调试域名校验需要操作者在开发工具里按需设置；仓库默认 `urlCheck: true`，不降低正式校验。Dev 登录仅使用后端明确配置的演示用户，不能用于真实微信支付。

每次修改源码后重新 `npm run build`；dist 为生成物，不手动编辑或提交。

## 已实现闭环

- 首页轮播、四类筛选、商城入口、活动卡片、触底分页、下拉刷新。
- 活动详情展示时间、地点、集合点、容量、截止时间、正文与分享。
- 用户主动报名时调用 `wx.login`，只将一次性 code 交给服务端兑换；AppSecret/会话密钥不进入前端。
- 可添加/删除多位参与人，逐人填写姓名、18 位身份证号、手机号；信息使用同意 → 服务端按实际人数占名额 → 成功页显示人数与人员名单；取消/错误不宣称成功。
- 商城商品、详情、数量、收货信息、订单、继续支付与取消回库；`wx.requestPayment` 使用服务端签名参数，只有服务端 PAID 才显示支付成功，回调延迟显示确认中。
- 我的报名含确认与取消历史；详情精确读取本人当前报名，不用分页列表猜测状态。
- 取消报名二次确认；服务端最终判断截止、并发名额和重复报名。
- 登录中去重、报名提交锁、分页合并去重、请求 epoch 抑制过期响应；返回/重进详情同步真实状态。
- 空数据、加载、请求失败、重试、截止、满员、取消活动与收费活动暂未开放状态。
- 活动时间显式转换为 Asia/Shanghai（UTC+08），不依赖手机所在时区。
- 当前手机号校验针对中国大陆手机号；国际手机号未作为本期需求开放。

## 隐私和正式上线前置条件

登录账号与报名资料属于真实用户数据，其中身份证号属于敏感个人信息。报名需逐人填写姓名、身份证号和手机号，用于活动身份核验、组织与联系。生产上线前，运营方必须填写真实主体、处理目的、数据保留期限、删除/联系渠道，并在微信公众平台配置与实际后端一致的《小程序用户隐私保护指引》。当前说明页面明确提示此项，不能把未填主体的说明当作已完成合规。

微信平台还需配置小程序 AppID、服务端 AppSecret（仅服务端秘密配置）、合法 HTTPS request 域名，以及活动远程图片对应下载/图片访问域名。真实支付还需商户号、商户私钥、微信支付公钥、APIv3 密钥及 HTTPS 回调。部署和绑定域名由运营方另行授权。图片默认六张内置素材可离线读取；其他 `/assets/*` URL 被解析为后端 origin 下的资源，只有 HTTPS 远程链接被接受。未接入定位、自动读取手机号、通知订阅或通讯录等权限；支付由用户主动发起。

## 小程序内管理与用户闭环（2026-10-26）

“我的”现在独立于“我的报名”：登录后请求 `/me` 确认实际身份，普通用户只有自己的报名和活动入口；管理员可进入活动管理。底部“管理员身份验证”是身份校验入口，不是授予权限，使用既有服务器管理员账号密码。密码仅用于当前 HTTPS 登录请求，不写入小程序存储、不记日志；成功后只存服务器会话令牌。管理页面再次调用 `/me` 校验，后端所有 `/admin` 接口仍执行角色授权。

管理账号和微信账号是不同账号，各自拥有各自的报名记录。切换为管理员后不会把原微信用户的报名合并到管理员；退出后重新微信登录即可恢复查看原账号记录。失败的管理登录不会清除原微信会话。退出、账号切换和页面隐藏会清理私有视图，旧请求不能回填新账号的页面。不得通过改客户端 role 字段获取权限。

新增路由：
- `pages/registrations/index`：自己的报名列表，全部/已报名/已取消采用服务器全量状态筛选与分页；“已报名”是状态，不代表活动尚未结束。
- `pages/signup-success/index`：报名确认结果。POST 返回确认报名后进入；页面再次按当前会话查询有效报名和活动，确认报名编号、活动编号、状态一致才显示成功。仅拼接链接不能伪造报名结果。
- `pages/admin-login/index`、`pages/admin-activities/index`、`pages/admin-editor/index`、`pages/admin-roster/index`：管理员身份验证、活动列表、创建/编辑、报名名单。详见 `mini-admin.md`。

活动列表继续支持分类切换和分页，迟到响应不能覆盖更新的分类结果。报名失败或响应异常提示到“我的报名”核对；不会将网络成功或空响应当作报名已确认。我的报名中的取消操作通过活动详情执行，后端截止时间和活动状态规则仍然生效。

测试包含 Page/wx 事件模拟、请求竞态、权限返回、确认结果和导航行为。此类测试不是微信开发者工具或真机测试；发布前仍需完成实际平台验证。

## 动态隐私政策与用户协议

- 新增独立 `pages/login/index`：先获取后台已发布的两份文档，分别成功打开正文、主动勾选后调用微信登录；不输入微信密码，不自动获取头像或手机号。
- 隐私页现在读取服务器公开已发布版本，可通过 `kind=PRIVACY|TERMS&version=数字` 查看不可变历史；使用普通文本展示，不执行 HTML。
- 微信登录及报名请求携带确切 `privacyVersion`、`termsVersion`。提交前刷新当前版本，发布变化或服务端拒绝旧版本时清除勾选并提示重读；草稿修改不影响同意。
- 已有用户在“我的”能看到协议更新提示，点击后仅追加当前用户同意记录，不重新创建身份。不确认不妨碍公开浏览、查询历史报名、按原规则取消报名或管理员维护。
- 生产尚未发布完整两协议时禁止新微信登录与报名，明确显示原因；管理员身份验证不受阻，管理员可先发布经运营方审核的正文。开发登录同样携带显式同意版本。
- 小程序自定义协议不能代替微信公众平台的隐私保护指引及相应平台配置。真实平台授权、AppID 和法律文本审核需运营方完成；本仓库不证明上线合规。
